# Nyrva v1.0.3 — Codex native statusline compatibility

Patch release for the Codex native statusline integration.

## Fixed

- Accepts the Codex `tui.status_line` configuration as either `array<string>` or `null`.
- Treats an explicit `null` as a disabled native status line instead of rejecting the configuration.
- Keeps an absent `tui.status_line` distinct and uses the Codex native default items as the planning baseline.
- Preserves existing string-list items while Nyrva manages only `five-hour-limit` and `weekly-limit`.
- Continues to reject malformed/non-string statusline values without modifying the user's configuration.
- Adds regression coverage for absent, null, valid string-list and invalid statusline configurations.

## Included from v1.0.2

- Windows NSIS per-user PATH integration and fresh-process package acceptance.
- Codex app-server configuration integration and the Rust compilation fix from v1.0.1.

## Distribution

The release workflow rebuilds and verifies the Windows NSIS installer, Debian package and AppImage from the exact tagged commit. The GitHub Release is created as a draft only after all release gates pass.
