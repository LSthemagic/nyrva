# Nyrva v1.0.2 — Windows CLI PATH validation

Patch release focused on the Windows installer and standalone CLI discoverability.

## Fixed and hardened

- Keeps the per-user NSIS installation directory persisted in `HKCU\Environment\Path`.
- Broadcasts `WM_SETTINGCHANGE` after PATH changes.
- Strengthens Windows package acceptance so CI no longer makes the CLI resolvable by manually prepending the installation directory.
- The package test now reconstructs a fresh process environment from the persisted Machine + User PATH values and requires `Get-Command nyrva-telemetry.exe` plus a real CLI invocation to succeed.
- Preserves duplicate-safe install/repair behavior and Nyrva-only PATH cleanup on uninstall.
- Includes the Codex native statusline compilation fix from v1.0.1.

## Windows note

Processes that were already running before installation keep their old environment block. After installing, start a genuinely new terminal process before testing `nyrva-telemetry top`.

## Distribution

The release workflow rebuilds and verifies the Windows NSIS installer, Debian package and AppImage from the exact tagged commit. The GitHub Release is created as a draft only after the release gates pass.
